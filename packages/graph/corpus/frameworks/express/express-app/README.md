A small Express API with two applications (`app` in src/app.ts and `admin` in src/admin.ts), two routers mounted under `/users` and `/items` (one made through an aliased `Router as makeRouter` import), a router never mounted, middleware added with `use` and per route, an error handler, a route path built from an environment variable, a handler wrapped in `asyncHandler(...)`, an object of the repository's own with a `get` method, and a supertest test. The change edits `getUser` and deletes `removeUser`, which a route still names. A route graph that binds handlers by name, or drops a registration when its handler goes, would lose `DELETE /users/:id` and could bind the wrapped `getItem` as if it were the handler. The case checks that every route keeps its full pattern under its mount prefix and its middleware in order, that the deleted, wrapped and computed handlers leave their registrations in place with an unknown each, that the admin application's `/health` stays apart from the main one's, that `app.get("/health", ...)` on an object of src/cache.ts is no route, and that the supertest request reaches `GET /users/:id` of the application it was given, as likely, while the test's direct call of `getUser` is certain.
