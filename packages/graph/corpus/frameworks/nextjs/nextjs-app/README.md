A small Next.js storefront with both routers: app router pages under a route group `(marketing)`, a dynamic `[slug]` segment, a dashboard with a layout, a loading and an error boundary, a route handler exporting GET and POST, a server action in a "use server" file, client components, a private folder `_drafts`, a parallel slot `@team`, a pages router with a page and an API route, and a middleware whose matcher selects the dashboard. The change edits the GET handler. A route graph that read the tree naively would serve `/(marketing)/about`, `/_drafts` and `/@team`, merge the two routers, or run the middleware for every route. The case checks each URL and its handler, that the private folder serves nothing, that the parallel slot is an unknown rather than a guessed route, that the server action is a POST entry with no URL of its own, and that the middleware applies to `/dashboard` and not to `/` or `/api/users`.
