The repository's own package `example.com/fakehttp/http` is imported as `http`, and as `httptest` in the test, so every call reads like the standard library: `http.NewServeMux()`, `mux.HandleFunc("GET /home", home)`, `mux.Handle("/wrapped/", logging(home))`, `http.HandleFunc("/top", home)`, `http.ListenAndServe(":8080", mux)` and `httptest.NewRequest("GET", "/home")`. The project never imports net/http. A plugin that trusts the local name `http`, the method names or the shape of a call would report two muxes (one of them a default mux), three routes, a middleware edge, a request link and a go test role. The case checks that none is reported: `http` is net/http only when the import resolves to the standard library, the default mux exists only for a project that registers on net/http, and test functions get the test role only in a project that serves net/http. The change edits `home`, which the test calls directly.
