router.ts binds `const handlers = { save: onSave, remove: onRemove }` and route calls `handlers[k](id)`. The change edits onSave. The computed call has no name to bind, so a graph without value tracking only reports a gap that could reach any function of the project. Because handlers is a literal table in the same file, the call may run exactly its entries: route must be a possible caller of onSave and onRemove through may_invoke edges, each entry a certain uses_value reference, and the dynamic unknown must stay at the call with its scope narrowed to the file.
