router.py binds `HANDLERS = {"save": on_save, "remove": on_remove}` at module level and handle calls `HANDLERS[k](x)`. The change edits on_save. The computed call has no name to bind, so a graph without value tracking only reports a gap that could reach any function of the project. Because HANDLERS is a literal dict in the same file, the call may run exactly its values: handle must be a possible caller of on_save and on_remove through may_invoke edges, each dict value a certain uses_value reference from the module, and the dynamic unknown must stay at the call. Its scope stays the project: HANDLERS is a module global that any module importing router may change, so a function it never named may be called.
